# hfauto の汎用化と継続運用の改良計画

未知の生成物を含む反応ネットワークを育て、指定した条件で比較し、初期系から進みやすい経路を根拠付きで判断する。そのために、探索候補を順番に処理する構成から、検証した状態と素反応を共有して次の計算を選ぶ構成へ移す。

本書を今後の改良計画の正本とする。[design.md](design.md) は実装済みの設計、[validation.md](validation.md) は評価結果、[environment.md](environment.md) は実行手順を扱う。同じ計画を各文書へ複製しない。外部ライブラリの置換は保留し、現在のエンジンで成立する改良を先に測る。

開始時点は 2026 年 10 月 6 日の作業ツリー。R10 の W1〜W4 はコミット済み、W5 の実装と部分評価は未コミット、W6・W7 は未着手である。以下の項目は実装計画であり、現在の機能として読まない。

## 1. 目的と完成条件

1. **未知反応の発見**: 生成物や機構を入力しなくても、初期分子、会合体、到達した生成物と断片から素反応の候補を広げ、停留点と接続で確かめる。
2. **条件付きの比較**: 温度、標準状態、分圧または初期量、電子状態、理論水準をそろえ、何を比較しているかを示す。条件や証拠を欠く行には順位を付けない。
3. **初期系の主要経路の条件付き判断**: 到達可能性、競合する経路、配座、捕獲律速、未探索部分を含めて判断する。障壁表だけから実際の生成物比や速度を断定しない。
4. **シンプルな継続基盤**: 一つの事実に一つの登録経路を持ち、止めて再開できる。第三者が入力、計算、判定、未解決、次の仕事を追える。

成功は候補数、合格行数、コード行数の増減だけでは測らない。同じ計算費用で得た検証済みの経路、独立した参照に対する正しさ、判断の再現性、不要な仕事の削減で測る。

## 2. 対象範囲と判断の条件

最初の実証範囲は気相の主族分子と非共有結合錯体、閉殻一重項と単一参照で扱える開殻系とする。元素を受け付ける範囲と、精度を検証した範囲は別に表示する。遷移金属を入力できることは精度の保証にしない。

小分子での意味と接続を先に確かめ、次に 15〜35 原子程度の系で費用を測る。40〜80 原子を目標から外さないが、現在の 4 コア環境で全面的な DFT Hessian を実用時間に収められるとは約束しない。資源と実測費用に応じて検証する点を絞り、未検証の点を結果に残す。

| 条件 | 最初の扱い |
|---|---|
| 原子・電荷・スピン | 各素反応で原子と全電荷を保存。多重度は宣言値と許される結合から扱い、別面への遷移を暗黙に作らない |
| 計算面 | 同一電子状態の断熱面を基本とする。SCF が収束したことと基底電子状態にあることを区別する |
| 系の供給 | 閉じた初期混合物か、供給する単量体を固定したリザーバーかを明示。宣言していない原子を生成しない |
| 会合・成長 | 初期成分と発見した断片の組合せ。原子数、分子数、反応分子数、成長段数の上限を入力で固定する |
| 比較 | T、標準状態、分圧・活動度の仮定とエネルギー層を添える。異なる条件の序数を混ぜない |
| 速度・生成物比 | 対応する速度モデルのある範囲だけ。必要な速度定数が未決なら主要経路も条件付きまたは未決 |

溶液、表面・周期系、MECP、強い多参照、開殻一重項の一般的な扱い、遷移金属精度、VRC-TST、マスター方程式、多次元トンネルは当初の完成条件に含めない。これらを扱う拡張は、必要な物理モデルと評価を別途決める。

## 3. 現在の構成から変える点

| 現在の制約とコード | 必要な変更 |
|---|---|
| 同じ状態対を一つの問いにまとめ、TS を貸して最初の結論を共有する。[hypotheses.py](../hfauto/chemistry/hypotheses.py)、[reaction_paths.py](../hfauto/stages/reaction_paths.py) | 問いと検証済みの素反応を分け、同じ状態対の複数の TS と電子状態を保存する |
| 反応は一つの組成の両端を中心に持つ。[records.py](../hfauto/core/records.py) | 両側を化学種と個数の組として持ち、分離、再会合、新しい組成への成長を扱う |
| trial の編集類ごとに、駆動距離の最小の配座と編集を一つ選ぶ。[trials.py](../hfauto/chemistry/trials.py) | 複数の配座・配向・候補生成手順を有限の予算で試し、幾何の不成功を反応不存在と扱わない |
| 低レベルで届いた辺の篩を DFT の入口にする。[selection.py](../hfauto/chemistry/selection.py) | 低レベル basin のない初期会合体、純粋な開裂、補完探索にも入口を設け、篩の見落としを監査する |
| 同じ状態の最小 G を代表にする。[thermochemistry.py](../hfauto/stages/thermochemistry.py) | 配座を保存した上で、平衡の仮定と集約の規則を明示する |
| SCF 解の引継ぎと照合は主に親計算と ⟨S²⟩。[gates.py](../hfauto/chemistry/gates.py) | 観測した情報で保証できる電子状態だけを認証し、区別できない枝を確定扱いしない |

現在の不具合をすべて直してからこの変更に進む必要はない。動作基準を保存し、小さなパイロットで新しい探索管理が目的と費用に合うかを先に判断する。W6・W7 を旧設計のまま全部完成させることも、全面 rewrite も前提にしない。

## 4. 共有する化学の事実

以下の単位を分ける。名前は意味を示すものであり、表ごとに新しいクラスや永続ファイルを作る要求ではない。実装前に、各項目の作成者と利用者を一組ずつ定める。

| 単位 | 保持する意味 | 合流させないもの |
|---|---|---|
| 化学状態 state | 組成、電荷、結合グラフ、区別できる立体。原子番号との対応 | 区別できない電荷分離や立体を推定で確定した状態 |
| 盆地 basin | 指定した計算面の極小、構造、同一性判定に使う E と証拠 | 同じグラフの別配座、別の電子解 |
| 電子状態 | 宣言した多重度、親の SCF 解、得られた観測とその限界 | 同じ多重度・同じ ⟨S²⟩だけで同一とした空間電子状態 |
| 素反応 elementary step | 実測した両側の basin または分離状態、原子対応、TS または障壁なしの経路、計算面 | 同じ反応式に属する別 TS、別配座経路、別面 |
| 探索の問い hypothesis | 調べたい端点・編集・接触と試した種、残る未回答 | その探索が偶然到達した別の素反応 |
| 反応条件 | 初期組成と量または供給、T、標準状態、比較・速度モデル | 条件を変えた評価値 |

ネットワークは、反応物・生成物の状態の多重集合を結ぶ複数辺とする。たとえば A + B → C と A + B → D、C → E + F を同じ形式で扱い、逆反応は同じ証拠と同じゼロから評価する。会合の複合体と分離した A + B は区別する。

TS が別の端点を結んだら、その素反応を登録して元の問いは未回答のまま残す。同じ素反応を再発見した場合は証拠と探索の出所を共有するが、別 TS を同じ状態対というだけで捨てない。多段経路は辺の列として照会し、親を split 子の管理主体にしない。

電子状態の記録は、既存 Evidence と親計算参照から始める。全エンジン共通の完全な電子状態 ID や大量の軌道診断を先に設計しない。枝の区別に既存観測で足りない場合は、その判断を未検証とし、必要な追加観測を反例で決める。

## 5. 探索と検証を回す仕組み

流れを「状態・断片の登録 → 次の問いと種の選択 → 計算 → 化学判定 → 事実の登録 → 次の仕事」にする。安い計算は種と優先順位を作り、高い計算は読む事実を確かめる。低レベルの否定を DFT の不存在の証明にしない。

### 5.1 断片と組合せの成長

- 到達した構造の連結成分を断片候補として登録する。断片の電荷配分と許される多重度が決まらなければ、その分岐を未確定として扱う。
- 断片の DFT 極小とエネルギーを必要なものから計算し、宣言済みの単量体だけに分離ゼロを限定する構成を改める。
- 初期成分、到達した分子、断片から、一分子の変換、開裂、二分子の再会合を作る。同種分子の複数個使用は初期量またはリザーバーと照合する。
- 生成物に初期成分が付加する成長も許すが、原子数・分子数・成長段数を超える問いは作らず、止めた範囲を出す。
- 原子対応、全電荷、スピンの扱いを各反応で照合する。候補の組立てでは同じ親構造の原子を二重に利用せず、経路評価では化学量論と初期量を照合する。

### 5.2 複数の探索と配置

既存の結合編集と NT2 を維持し、まず純粋な開裂と、分離断片からの接触を補う。宣言端点、mode-follow、NEB/string の種も同じ待ち行列へ渡す。候補生成器ごとに専用の判定や再利用機構を追加しない。

配座・配向は、状態ごとの代表一つで完了としない。最初の代表、既存配座と異なる代表、接触方向の異なる代表を順に試す。候補の重複は原子対応と構造で除き、特定の系に専用の配置規則を加えない。

低レベルで初期状態が崩れた場合も入力構造と分離状態を保持する。反応性ラジカル対などには、少数の DFT 入口計算を割り当てる。これは無制限の DFT 探索ではなく、低レベルの面による見落としを減らす入口である。

### 5.3 予算と救済

探索試行、配置、DFT 検証に予算を分け、全体の上限と状態ごとの取り分を持つ。新しい状態と未探索の種類に最低限の取り分を残し、安い辺の大量生成だけで予算を使い切らない。残りの予算は新しい事実が得られた方向へ回す。

失敗への対応は、SCF の新しい推定、最後の構造からの継続、別配向、別の種に限定して有限回試す。system 名による救済、同じ失敗の無限再試行、収束閾値を合格まで緩める操作は導入しない。救済後も化学の判定基準は変えない。

止めた run の再開では、計算済みの結果だけでなく、使った予算、残る種、未探索状態を戻す。中断によって満額の予算を再付与しない。運用の停止時間は化学予算と分ける。

### 5.4 検証と層の経路

極小・TS は勾配と Hessian で停留性を確認し、TS は一次の鞍点と両側の到達先を確認する。QRC で曖昧なものだけ追加の下りや IRC を試し、配座の同一性と化学状態の同一性を混ぜない。

順位に使う層は停留点だけでなく、障壁なしとした経路の重要な節点にも適用する。山が現れたら候補として検証する。節点の間に未解像の領域が残れば「この解像度での判定」として扱う。SP の差替えだけで別の PES の停留点を認証したとは言わない。

## 6. 比較と主要経路の判断

配座の G と TS をまず個別に残す。配座間平衡を仮定する場合は、縮重を含む分配和で状態を集約し、適用した仮定を出す。配座間の移動が競合反応より速いと扱えない場合は、個別の basin を残して評価する。

比較は、同じ条件の ΔE、ΔG_rxn、ΔG‡、経路の共通ゼロに対する量を分ける。電子障壁を熱化学の障壁と比較しない。barrierless は捕獲律速の別群とし、0 kcal/mol の TST 障壁にして通常の順位へ入れない。

主要経路は二段階で扱う。最初は、初期系からの到達経路、分岐、障壁、不足する速度情報を示す。次に、素過程ごとの速度モデルがそろう範囲だけ、初期量または分圧を用いた質量作用モデルで時間と生成物分布を評価する。

通常の TST を用いる辺、捕獲モデルを必要とする辺、圧力依存やトンネル等を扱えない辺を区別する。未決の速度を適当な定数で埋めない。主要経路の結論が未決の辺に依存するなら、その依存関係を示して判断を止める。

不確かさは、電子エネルギー、構造・電子状態、配座・熱化学、探索不足、速度モデルの五つに分ける。qRRHO の感度幅だけを全誤差としない。数値で見積もれるものは条件を振って順位や分岐が変わるかを調べ、数値化できないものは結論の限界として付す。

## 7. 責務の配置

| 場所 | 担うこと | 持ち込まないもの |
|---|---|---|
| core | 計算証拠、状態・素反応・問いの必要最小限の記録、条件、永続参照 | 化学判定、探索ループ、エンジン固有の例外 |
| chemistry | 状態・盆地の比較、編集・断片・組合せ、停留性・接続判定、熱化学・比較・速度の数理 | subprocess、run の更新、system 名の分岐 |
| drivers | 種から検証までの有限の手順、次の仕事の選択、事実を登録する一つの経路 | CSV/HTML、別々の同一性や救済規則 |
| stages | manifest の入力を集め、driver を呼び、成果を返す | 独自の registry、探索の二重実装、共有データの巻戻し |
| backends | 必要な計算を実行形式へ翻訳し、観測値と継続用ファイルを返す | 化学の合否、候補選択、上流の状態登録 |
| execution | ジョブ鍵、キャッシュ、停止・継続、資源配分、永続化 | 化学的な順位、物理モデルの選択 |
| reporting | 反応式・条件・出所・費用・未解決を事実から表示する | 表示のためだけの判定や計算 |

registry は一つの所有者が更新し、計算 worker は証拠だけを返す。stage 間の受渡しは manifest を維持し、全体を汎用ワークフローフレームワークへ作り直さない。

エンジン境界では E、勾配、Hessian、構造、観測した LOT、親の電子解と利用できる継続ファイルを扱う。必要な証拠を返せない task は未対応または未検証にする。巨大な能力行列、各タスクの別 Protocol、全ジョブへの高価な診断は追加しない。

新しい観測は、既存観測では誤った結論になる反例と、その値を読む判定がそろったときだけ足す。追加で解けない課題が残った段階で、外部ライブラリの機能拡張や置換を候補として測る。置換する場合も化学記録と実行基盤を維持する。

## 8. 根本から整理するもの

整理を最後の美化作業にしない。各実装単位で、新しい作成者と利用者をつなぎ、置き換えた経路を同時に削除する。

| 維持する基盤 | 削除または統合する対象 |
|---|---|
| Evidence、観測 LOT、FileRef と内容 hash、fail-closed | 同じ判定を adapter、stage、report に複製する処理 |
| JobStore と、実行資源を化学の鍵から分ける原則 | 古い schema のためだけの常設互換層、読まれないレコード欄 |
| basin 同一性、純関数の化学判定、共通の反応計算点 | split、same_as、ts_calc、_lend に分散した事実再利用 |
| 有限の探索手順、共有した下り・継続、core の資源上限 | 各経路専用の rescue、親子 case の予算管理、二重の探索待ち行列 |
| 実出力 golden、fake PES の意味のある試験 | 実装をなぞるだけの試験、廃止仕様や無意味な行数目標 |

既存の steps、layer_verdict、dE_act_path_kcal などは、欄があることを採用理由にしない。新しい経路照会・層の評価が直接読むものだけ残し、読む場所のない欄は削除する。source_minimum 等の古い manifest 専用欄も移行後に除く。

旧 run は自動的に新しい意味へ読み替えない。旧版と入力・結果を保存して証拠として読めるようにし、新版の再計算用入力を明示的に移す。互換性が必要なら一度だけの変換に限定し、本体に古い schema を残さない。

文書は README を入口、design を現在の実装、environment を手順、validation を測定結果、本書を未完了計画にする。古いレビューの提案は現行の設計本文へ再掲せず、必要な根拠へだけリンクする。重複、既に無効な手順、誤った現在説明は本文から削除し、変更履歴は Git と根拠資料で追う。

## 9. 実装単位と受入基準

| 単位 | 前提 | 成果と受入基準 |
|---|---|---|
| P0 動作基準の保存 | なし | W5 作業差分、未追跡入力、環境 pin、評価元 run、未達項目を対応付ける。既存成功と既知失敗を固定し、W5 を全面合格と扱わない |
| P1 問いと事実の分離 | P0 | 状態・basin・電子解と素反応の最小モデル、単一登録経路。同じ状態対の異なる TS を保持し、再発見は一辺。別端点に到達しても元の問いは未回答 |
| P2 探索管理のパイロット | P1 | 既存探索、純粋な開裂、少数の接触配置を同じ待ち行列へ。予算の保存と低レベル basin なしの DFT 入口。既存系と新しい二つ以上の反応型で費用対到達を比較し、採否を決める |
| P3 断片と組成の成長 | P2 採用 | 断片の極小、分離ゼロ、再会合、初期成分の追加。同じ構成で開裂→再結合と生成物→次の付加を発見し、原子・電荷・供給量・上限を保存する |
| P4 条件と熱化学の統一 | P1、層の経路は P2 | 配座の保持と集約、条件付き比較、層の経路判定。逆向きと共通ゼロが一致し、条件不足・層不足・電子状態不明を順位に入れない |
| P5 主要経路の評価 | P3、P4 | 到達経路と未決分岐の表示。対応した速度モデルだけで条件と初期量から評価し、競合反応の解析解と保存則、平衡モデルでの詳細釣合いを満たす |
| P6 移行と運用整理 | 採用した P1〜P4 | 鍵と schema を一度の境界で移し、旧再利用・split 管理・unused 欄を削除。停止再開、キャッシュ、第三者の再開手順を確認。P5 は後から同じ事実を読める |
| P7 独立評価と規模の拡張 | P2 以降の各採否、最終は P6 | 未調整の系で発見、精度、費用、判断の限界を評価。小分子から中規模へ広げ、最終状態の評価と残る対象外を公開する |

P1 はまず小さい反応ネットワークを fake PES と保存済み証拠で作る。P2 のパイロット中は既存 pipeline の動作基準も再現できるようにし、出力は新しい run に分ける。パイロットを採用したら旧探索管理を削除し、恒久的な二方式を維持しない。

P2 で検証済み経路が増えず費用だけが増える場合は、全体へ展開しない。候補の順序、配置の数、低レベル篩の監査配分を見直してもう一度だけ比較し、それでも改善しなければ対象と方法を再設計する。

初回の実 QM パイロットの暫定上限は、4 コアで壁時計合計 4 時間相当（57,600 core 秒）とする。各runの予算はこれを超えないよう系と点数を開始前に確定する。実測から不足が分かった場合は追加試験を別に計画し、同じ試験を無制限に延長しない。予算不足は未完了として残す。全面評価の費用は opt、freq、探索の実測から積み上げる。

## 10. 評価の設計

回帰、独立精度、未知発見、速度判断、運用を分ける。新しい方式で結果が変わる場合は、物理モデル・定義・バグ修正・探索追加のどれに由来するかを示す。旧値に合うように期待値や閾値を動かさない。

| 評価 | 使う証拠と合格の判定 |
|---|---|
| 記録・登録 | 原子の並替え、回転、鏡像、同状態対の別 TS、再発見、別端点到達を fake PES と保存証拠で確認。事実の消失・重複・原子対応の誤りは 0 件 |
| 数値と接続 | 独立した勾配・Hessian、必要時 IRC で停留性と接続を確認。証拠のない受理は 0 件。曖昧な QRC を未解決として数える |
| 既知端点の精度 | BH76 の参照、ゼロ、比較量を守り、電子障壁と幾何の寄与を別に測る。既定の per-row 1.0、幾何寄与 0.3 kcal/mol を拡大しない |
| 未知発見 | 調整用と未調整の評価系を分離。単分子、H 移動、置換、付加、純開裂、再会合、成長、配座依存を含め、既知の低障壁経路の到達率と誤同定を種類別に出す |
| 探索の改善 | 同じ入力・資源・予算で旧方式と比較。パイロットの既知主要経路を失わず、新しく追加した反応型の検証済み経路を得る。生の辺数で代用しない |
| 比較と速度 | 逆反応、標準状態、量の変化、縮重、配座集約、競合・逐次反応の小さい解析モデルで確認。保存量、平衡モデルでの詳細釣合い、未決速度が結論に与える範囲を確かめる |
| 再現性と費用 | 新規 run を複数回行い、状態・素反応と条件付き結論を対応付ける。core 秒、壁時計、最大メモリ、再利用、検証済み辺あたりの費用を並べる |
| 運用 | 計算中・登録前・登録後の停止から再開。予算と事実が増殖せず、再開しない run と同じ到達集合になる。独立ジョブの変更だけが再計算される |

未知発見の評価入力には正解生成物や原子対応を渡さない。正解側は出典と原子対応を保持し、組成式の一致だけで生成物や経路の一致を判定しない。未調整の系を一度でも調整に使ったら、その系は以降の holdout と呼ばない。

参照は validation に入力・出典・比較量・採否基準を保存する。BH76 の selection と holdout は既存の分割を維持する。既存 regression の 0.01 kcal/mol は数値再生の幅であり、化学精度の保証に流用しない。

不明、予算不足、数値失敗、対象外を分母から落とさず、到達率と費用に残す。計算した領域の収束を示すことと、全反応を網羅した証明を区別する。

評価は安い順に行う。純関数・fake PES → 保存証拠の再判定 → 各エンジンの少数 smoke → 小分子のパイロット → 未調整系 → 中規模。意味が変わらない部分の全面 QM 再計算や、全ジョブへの重い追加診断を既定にしない。

## 11. R10 の残作業との対応

| R10 の項目 | 本計画での扱い |
|---|---|
| W5 の停留性、共通の下り、QH、電子準位、失敗の閉じ込め | P0 の動作基準として保存。acac の認証未達、S5 の境界、並列化の費用を改善済みと偽らない |
| W6 の事実の登録簿と TS の貸し手の両端 | P1 で問いから独立した複数辺に変更。状態対一意の登録簿で終わらせない |
| W6 の TS 種の順序と層の経路 | P2 の有限の種の選択、P4 の経路評価へ統合 |
| W7 の鍵、版数、deck、SCF guess、schema 移行 | P6 で一括移行。QRC の親 guess は電子解の引継ぎの一部として評価する |
| W7 の split 削除と整理 | P1 の経路照会へ置換した時点で削除。旧管理の上へ別 registry を積まない |
| VAL10、BH76 の取り直し | P7 の独立評価へ再編。旧計画の全面検証をパイロット前の必須作業にしない |

外部ライブラリを変える判断は、P2〜P4 で必要な計算や観測を現在の構成で得られない場合に行う。ライブラリ置換を、このモデル変更や独立評価の代わりにしない。

## 12. 第三者が再開する手順

1. README から本書、design、environment、validation を読む。まず実装済みの範囲と未完了の実装単位を区別する。
2. git status、現在の HEAD、保存済み差分と未追跡入力を照合する。W5 の変更を reset せず、新しい作業と混ぜる前に動作基準を保存する。
3. environment の WSL prod venv と site を確認する。通常の run は使用するエンジンだけを点検し、site 全体を調べる必要がある場合に hfauto doctor を使う。既存 run の status と manifest の読み取りから始め、古い schema の run を新版で上書きしない。
4. 作業対象の実装単位、前提、受入基準、利用する評価入力、費用上限を確認する。依存する未完了項目があれば、独立した fake／保存証拠の作業から始める。
5. 検証は WSL で、その変更に対応する unit・golden・integration、ruff、import-linter、型検査を行う。新しい化学的分岐は少数の実計算で確かめる。
6. 実計算は新しい ext4 の run ディレクトリへ出す。既存 run は再判定の元として保存し、再開は同じ条件の run に対して行う。
7. 結果を validation に記録し、roadmap の該当実装単位だけを完了または未達へ更新する。統合した設計は design へ移し、本書の未完了計画から外す。

既存の読み取りと比較には次を使える。RUN は対象の run、RUNS は同じ評価入力の run を並べたディレクトリに置き換える。

    hfauto status RUN
    hfauto case RUN REACTION_ID
    python validation/check.py RUNS CASE_NAME
    python validation/check.py RUNS --require-complete

check.py は既存 regression と参照矛盾の確認であり、新計画の未知発見や速度判断の合格を保証しない。最後のコマンドは fresh の全系と境界系の二回目を要求する。旧単独runや再生との比較では二回目未実施を NOT_CHECKED と明示する。

記録するのは、版と差分、入力・条件、実行コマンド、run の場所、評価対象、得た事実、失敗と未探索、費用、次の具体的な仕事である。作業履歴用の別計画書や、読む場所のない診断ファイルを増やさない。
