## 0. 要旨

### 0.1 目的に対する総合評価

hfauto の目的は「気相の任意の主族分子(40〜80 原子まで)と非共有結合錯体について、生成物を仮定せずに素反応を見つけ、DFT で検証した停留点と接続から熱化学を求め、正直に順位を付ける」ことである(README.md 冒頭、docs/design.md)。

### 0.4 維持すべき土台

- Evidence の 7 保証、観測した Level の厳密な照合、合否をゲート関数(`chemistry/gates.py`)だけが決める構成、fail-closed な Failure。
- 内容アドレス型の JobStore と、ExecutionSpec を鍵の外に置く原則。stage 契約と単一の入口。
- 二層の合成 G = E_layer + (G_GV − E_GV)。層がなければ PBE0 で代用しない正直な停止(energy_layer_missing)。
- 置換不変の同一性(Hungarian と Kabsch の交互反復。200 回のランダム試験で最悪 0.0023 Å)、鏡像を 1 basin として m で数える規約、像の job なしの join、既知の basin で freq を省く規則。
- ヒステリシス付きの極値の分類と、「連続経路の最大は鞍点の上界」という論法。安い順の漏斗(近道 → xTB NEB → DFT string)。
- shape_hessian による「方向だけ負」の整形、QRC の振幅の決め方(Goodman–Silva)、Registry と状態キーによる接続の判定。
- GFN2 は試料の生成だけに使い、エネルギーと状態は DFT で決める原則。ReaDuct の NT2→Bofill→IRC への委託と、低レベルでの検証の連鎖。
- GoodVibes のプロセス内呼び出し(==4.3.0 固定、golden test)。対称化した構造での射影振動。標準状態の補正。微視的可逆性による effective_barrier。
- 決定表を純関数として持つ構造。import-linter の層の契約、fake の解析的 PES による駆動論理のテスト、WSL の品質ゲート。

## 1. 本来の目的と要求

### 1.1 目的

1. 生成物を仮定せずに、与えた分子や組成から素反応を見つける。宣言した反応も同じ枠で扱う。
2. 見つけた反応を DFT の停留点(極小・一次の鞍点)と接続(QRC/IRC)で検証する。
3. 高い精度のエネルギー層と熱化学で、物理的に意味のある量(律速の自由エネルギー差)を求め、不確かさの範囲で順位を付ける。
4. 条件を満たさないものは推測で埋めずに止め(fail-closed)、何が分からなかったかを報告する。
5. 再現でき、来歴を辿れ、計算資源に比例して規模を伸ばせる。

### 2.2 要点

- **合否の判定が一か所に集まっている点は良い。** 一方で「判定の入力」(どの点、どの基準、どの計量)は散らばっている。これが本書の課題の多くに共通する形である。
- **費用は DFT の検証側に集中している。** 低レベルの探索・配座は 1% 未満。したがって「低レベルでは広く探し、高価な段の入口を化学の量で絞る」方向に改める余地が大きい(X5)。
- **データの流れは線形の pipeline。** 仮説の分割だけが stage 内の再帰で、ここに特別機構(_Book、same_as、Deadline の継承)が集まっている。
- **同一性は二本立てになっている。** 状態の水準(state_label)と basin の水準(identity.assign)。前者が弱い(1-WL、立体なし、閾値 1 本)ことが探索・仮説・熱化学の全段に効く。

### 3.5 規模の限界

- freq は 4 コア・def2-SVPD で、閉殻約 45 原子・開殻約 35 原子で timeout(14,400 s)に当たる見込み。継続はできない。

- CPU の DF Hessian(PySCF)に替えても、acac で約 15% しか速くならない(PG-09)。桁を変えるのは基底の規則(U0-P7)と並列化(U9-P2)である。

### 3.6 再現性

- VAL9 と R2(同じコード・同じ入力)で、鍵の一致は 451/907(49.7%)。同じ鍵の NWChem opt(4 rank)でも最終構造が 4.9e-6 Å ずれ、下流の鍵が分岐する。

- 打ち切られたのに rc 0: hono_walltime。

**改良案.**

- **U0-P1 電子状態の来歴を 1 規則にする(must、修正採用)→ X3。** U0 に固有の点は 3 つある。
  - 受理判定 `_rescue_changed` は残し、名前を `scf_noise` にする。
  - 「gnorm の停滞の検出」は採らず、反復の上限と既存の打ち切りだけにする。
  - 採否は、基準を先に宣言したプローブで決める。原子推定からの cgmin が成功した例はまだ 1 つしかない(`numerics/scf/cgmin`、166 s)。
- **U0-P2 層の汎関数を、参照集合の類別の誤差と SCF の健全性の 2 基準で選び直す(should、修正採用)→ X7。**
  - 既存の `known_endpoints` の system 群として、BH76 の部分集合を置く。参照値は文献の表を引用し、新しい YAML 層は作らない。
  - 候補は M06-2X、revM06、ωB97X-D3 の 3 つ。M06 系はメタ GGA の数値的な脆さが知られている(Lehtola & Marques 2022)ので、開殻の弱結合錯体での SCF の安定性を必ず測る。
  - 比べる量は振動なしの層の ΔE‡ にし、ΔG とは比べない。
  - 選定用と保留用(hold-out)に分ける。ただし統計力は弱いので、類別の MUE は「目安」として書く。
  - 偽合格の兆候: (a) 選定用と保留用に同じ反応がある。(b) 参照の構造で評価していて、PBE0 の構造での誤差を測っていない。(c) 易しい反応だけで差が出ない。(d) SCF の安定性を閉殻点だけで測っている。(e) 期待値を新しい層に合わせて書き換えている。
- **U0-P3 LOT を役割として 1 回だけ宣言し、密度収束を明示する(could、修正採用)→ X1・X7。**
  - 採るのは `levels: {low, stationary, energy}` の宣言(二重書きと `_check_stages` を削除)と、全タスクでの `convergence density` の明示だけ。
  - 閾値をすべて ε_E・r_B から導く案、λ_ZPE を独立の値として扱う案、Hessian の種類の欄は見送る(§4.0 見送り)。
  - tier 文字列を観測した Level の鍵に置き換える件は U9-P8 で扱う。
- **U0-P4 障壁の有無を順位の層で判定する(should、修正採用)→ X5(U5-P2・U8-P8 と統合)。**
  - 低スピン結合の組成の節点では、層でも高スピンの SP をとり、AP を層の LOT でかける。今の層には AP がないので、これは前提である。
  - P1 と P2 が前提。今の M06-2X では h_c2h4 の節点の SCF が解けない。
- **U0-P5 層の計算を「反応が読む点」に限る(must、採用)→ X5。**
- **U0-P6 低レベルの PES 仕様を 1 つの値にする(could、修正採用)。**
  - xTB の PES 仕様(gfn、etemp、chrg、uhf)を 1 つの型にする。SCC 失敗では「1000 K で 1 回だけ構造を得て、エネルギーは基準温度で取り直す」(ReaDuct の方式。worker.py:356-382)を xtb と pysisyphus(retry_etemp)にもそろえる。
  - 観測した Level を pysis と CREST の出力にも照合する。
  - CREST の TOML 化は、CREST に再試行を入れる場合に限る。

  - 中性系の gradient が約 3.7 倍、freq が約 2.7 倍軽くなる見込みがあり、測る価値は大きい。

- **U0-P8 電子状態の選択(could、修正採用)。**
  - 多重度は U1-P1(宣言を必須)で fail-closed にする。比較の段は需要が見えてから判断する。
  - 結合が切れる case の BS の試行(guess の swap)は、層での AP(P4)と一緒に設計する。

- **U0-P9 校正用 CCSD(T) の定義確認と対象の規則(could、修正採用)。**
  - OH と CH3O で、TCE の ROHF-CCSD(T) と UHF-CCSD(T) を、文献または PySCF の値と 0.1 kcal/mol 以内で照合する。標準の定義(Watts–Gauss–Bartlett)でなければ、UHF 参照にするか報告に明記する。

  - メモリはモジュールごとの固定配分の表にする(TCE の (T) は stack を多めに)。資源の失敗は NONZERO_EXIT と区別して分類する。O(o²v²) の見積もりとランクを半分にする継続は過剰なので採らない。

**見送り.**
- 停留点を M06-2X や範囲分離型にする: NWChem で解析 Hessian がない。構造の誤差(+0.31 kcal/mol)は汎関数の誤差より 1 桁小さい。
- 全ジョブの grid を xfine にする: fine と xfine の差は ΔE 4e-10 Eh。
- smear・FON・rabuck を最終解や救済の主手段にする: PES が変わる。h_c2h4 では DIIS 系 8 通りがすべて失敗した。
- 射影だけで SCF 失敗を直す: h_c2h4 では射影からも発散した。
- tblite `--spinpol`: SP でも 250 cycles で失敗した。
- CPU の DF エンジン: 約 15% しか速くならない。
- `linopt 0`: 系によって ±28%。
- 座標を丸めて鍵をそろえる: 境界をまたぐ確率が約 66% 残る。
- PySCF の stability() を既定の依存にする。
- CCSD(T)/G4 型を既定の層にする: 5 重原子で 1 点約 23 分。
- 走査の最大 1 点だけに層の SP をとる: 1 点では判定にならない。
- 状態照合の新しいゲートを足す。
- 閾値をすべて雑音の基本量から導く(U0-P3(3)): 値はほぼ変わらず、リファクタの割に効果がない。

**維持.** 二層の合成、正直な停止、Level の厳密な照合、停留点を PBE0-D3BJ(解析 Hessian、D3 のパラメータは正しい)にすること、パネルは表示だけ、GFN2 は試料の生成だけ、プロファイル点と freq を親の movecs から始める既存の配線、NWChem の native の saddle と driver。

**スコープ外.** MECP、多参照法、溶媒、遷移金属の検証、VRC-TST、ビット単位の決定性、GPU エンジン、最適化器の外部化(U6)、低レベルのサンプリング面の選択(U2)。

## 5. 横断的な根本原因と汎用設計

### X1 数値の頑健性: 判定はそれが定義された計量で行う

**根本原因.** 判定の多くが「その物理量が定義された計量」ではなく、手近な量で行われている。
- χ がデカルト計量で、正規モードは質量加重。
- 停留性が床のない二次モデルで、basin は RMSD 半径で定義される。
- 対称性の受理が同一性の雑音の尺度。
- 収束判定は autoz 内部座標なのに、下流の判定はデカルト。

**設計.**
1. **モードの性格づけは質量加重**(U6-P1)。重なり、χ、`_retry` のモード選択の 3 か所を同じ関数にする。
2. **停留性は basin 半径の信頼領域モデル 1 つ**(U3-P3、U6-P3)。
   - `vibrations.trust_region_step(H, g, x, radius)` → (ΔE_TR, s)。Moré–Sorensen の部分問題を解く。
   - 半径はデカルト(外部運動を射影)の r_B = BASIN_A·√N とし、identity の RMSD と同じ量にする。
   - 極小と TS の両方で、|H|(shape_hessian と同じ絶対値のモデル)の全モードで解く。TS で反応モードを除くと、反応座標方向の非停留を見逃す。
   - newton_push と `_soften` の分岐と capped を削除する。認証に落ちた点は x+s から正確な freq Hessian で 1 回だけ relax する。それでも落ちれば status は変えず notes に `not_stationary` を追記し(上書きしない)、thermo の blocker にする。新しい状態は作らない。
3. **閾値は「判定に意味のあるエネルギー」ε_E = 5e-5 Eh(約 0.03 kcal/mol)1 つで決め、SCF の雑音をその 1/10 以下に抑える。** 全タスクで `convergence energy 1e-8 density 1e-7` 相当を明示する(NWChem DFT の CONVERGENCE)。閾値を雑音から導くと、柔らかい系で認証が過剰に落ちる。
4. **プロファイルの判定関数は 1 つ**(U5-P1)。
5. **内部座標の微分は B 行列の行を共有**(U6-P8 の最小形)。

**検証.**
- QM なし: R2 の全 freq で ΔE_TR を計算し、極小 74 点は不変、acac の TS だけが境界になること。
- 実計算: opt の途中 frame(収束の 3〜5 歩前)から freq をとり、認証が落ち、1 回の TR relax で既知 basin に入ること。柔らかい 20〜30 原子の鎖を 1 系加え、ΔE_N では非停留、ΔE_TR では停留と分かれる点を示す。
- 偽合格の兆候: ε_E を上げて全点が合格する。小分子だけで「不変」を示し、境界の点(acac、平らな錯体)を通さない。仕上げの relax が別の basin に移るのに合格だけ数える。

**依存.** X3 の密度収束を前提にする。U3-P3 と U6-P3 は同時に入れる(停留性の関数は TS の流れ actions.py:346-354 でも使われる)。

### X2 対称性・縮重・電子項

**根本原因.** 「熱化学でどの対称性・どの縮重度で数えるか」という物理の問いを、外部の表(σ)、幾何の閾値(候補)、同一性の雑音の尺度(受理)、多重度(電子項)で代用している。

**設計.**
1. **σ と m は受理した操作の集合から数える**(U3-P1)。σ = 恒等 + 真回転の数、m = 回映がなければ 2。直線は 2 例外。
2. **受理は零点振幅のスカラー基準**(U3-P2、U7-P4 を統合した修正形)。
   - 外部自由度を射影した対称化の変位 d に沿って、½dᵀ|H|d ≤ ½ħω_d(ω_d² = dᵀ|H|d / dᵀMd)なら高い群で数える。
   - モードごとの基準は、多数の硬いモードに散った変位がすり抜けるので採らない。
   - 温度にも定数にも依らない。調和の推定は二重井戸の山を過大に見積もる側なので、保守的になる。
   - プローブでは、S6 の TS は VAL9(上昇 5.9e-5 < ½ħω_d 4.1e-4)でも R2(8.7e-7 < 1.8e-4)でも Cs になった。malonaldehyde の極小を C2v に平均した場合(上昇 27 kcal)は正しく棄却された(`u7_sym/mir.py`、`zpcrit.py`)。
   - **例外**: 対称化が電子の縮退をまたぐ場合(開殻の Jahn–Teller 系。例: CH3O の二重項を C3v にすると E 状態になる)は、PES が円錐交差で非解析的になり、調和の推定は無効になる。空間的な縮退が生じうる開殻の群への格上げは、今の雑音の基準のままにする。
   - **熱化学の整合**: E と振動数は非対称の極小 x から、σ・m(と慣性モーメント)は群からとる。対称を破るモードを qRRHO と σ・m で二重に数えない(今は対称化構造で慣性と振動を評価している。symmetry.py:12)。
   - 作業の順序: まず受理の基準を替える。VAL9 の S6 のように libmsym が候補を出さない事例が受理の側で救えない場合に限り、候補生成を同種原子の置換の後戻り探索(T3 の distaut.py が原型、1 件 0.02 s 以下)に替える。
   - 境界の入れ替わりはなくならず、遠ざかるだけであることを明記する。
   - SpeciesThermo に point_group・sigma・m の 3 欄を足す(G の項の出所の記録で、診断ではない)。
   - identity.is_chiral は統一しない(registry の構造の同一性の問いだから)。
3. **電子準位を 1 か所に持つ**(U1-P5、U7-P5 を統合)。
   - `chemistry/thermo.electronic(levels, T)` → G_el = −RT ln q_el(H_el を含む 1 項)と E_SO。GoodVibes には multiplicity=1 を渡し、S_el の二重計上を避ける。
   - 原子は (Z, 電荷) をキーにした NIST ASD の小さな表(基底項の J 準位)から引く。表の 2S+1 が宣言と一致したときだけ適用し、一致しなければ宣言の矛盾として止める。O の一重項や Cl⁻ への誤適用を構造的に防げる。
   - 直線の Λ>0 ラジカル(OH、SH、NO、ClO)は、宣言の任意欄 `electronic_levels: [(g, E_cm1)]` で与える。自動検出はしない。S6 の OH には宣言を書く。
   - E_SO は単離した原子と、宣言した直線ラジカルにだけ足す(合成エネルギーに入れ、ΔE と ΔG の両方に効かせる)。TS と錯体では消光すると扱う(G4/W1 と同じ慣例)。そのため、原子が関わる反応では障壁が |E_SO| だけ上がる。
   - 原子の補正は E_SO と −RT ln(q_el/(2S+1)) の両方を含む。²P では縮重度 4 の分の約 −0.41 kcal/mol が E_SO に加わる。
   - 検証: O(³P) の q_el(298) ≈ 6.7、Cl の E_SO −0.84、OH の q_el 3.02 と E_SO −0.20 を NIST から手計算で照合する。閉殻だけの系と Σ 状態の二重項だけの系(CH3O)では G がビット単位で不変であること。
   - 偽合格の兆候: GoodVibes に多重度を渡したまま(S_el の二重計上)。E_SO が G にだけ入り、dE 列や submerged の判定に入っていない。
4. **ZPE の scale**(U7-P7)は LOT の属性 1 値で、freq と zpe の両方に渡す。

### X3 SCF・電子状態の来歴

**根本原因.** アダプタの契約が「各ジョブは独立に SCF を解く」で、どの SCF 解かという来歴が LOT と構造に並ぶ量として運ばれていない。状態の連続性は用途ごとの個別配線でしか保たれず、救済は失敗した解を出発点にする。

**設計(U0-P1、U8-P3、U6-P6 を統合した修正形).**
1. **派生ジョブは親の解から始める。**
   - `scf_guess` に親の Evidence を渡す。アダプタは基底を比べ、同じなら `vectors input <file>`、違えば小基底を deck に宣言して `vectors input project <小基底> <file>` を書く。
   - 対象は、層 SP・パネルの DFT・プロファイル点・freq・QRC の両側の opt・継続の鞍点探索。protocols.py:104-105 の same basis の制約と、用途ごとの個別配線を削除する。
   - WFT の ROHF 参照に UKS の movecs を射影する案は採らない。WFT は対象の規則(4.)と原子推定からの ROHF で足りる。
   - プローブ: CH3O で PBE0/SVPD → M06-2X/TZVPD に射影すると、2 反復で同じ解に乗った(1.2e-8 Eh、⟨S²⟩ 一致。`/home/user/hfauto_r10_probe/nw_project`)。
2. **状態の照合.**
   - 同じ LOT の opt→freq は、今のエネルギー差(`gates._link_reasons`)のまま。エネルギーが最も鋭い指紋である。
   - LOT をまたぐ比較(freq→層、パネル)は、既存の量 |⟨S²⟩_SP − ⟨S²⟩_freq| ≤ spin_tol で行う。S5 の誤った解(freq は BS、SP は 0.759)はこれで捕まる。
   - Mulliken のスピン密度は、拡散基底で不安定で既定の出力にもないので、⟨S²⟩ で区別できない実例が出てから断片ごとの和の符号パターンとして足す。
   - QRC の両側に ⟨S²⟩ の連続性はかけない(結合の開裂で正当に変わる)。
3. **救済の梯子を 1 本にする.**
   - 親の射影推定で DIIS → 原子推定から cgmin(反復の上限、例えば 40)→ plain SCF で ⟨S²⟩ → 不成立なら、その点・その手法だけ `scf_unavailable` で閉じる。
   - 発散した attempt の movecs は使わない。engine.py:126-141 の `_resumed` の SCF 分岐と、input.py:63-69 の restart の使い方を置き換える。
   - 受理判定(同じ LOT のエネルギー差 ≤ SCF の雑音の床)はそのままにし、名前を `scf_noise` にする。gnorm の停滞の検出は足さない。
4. **WFT の対象規則.** DFT の参照が spin_ok を通り、低スピン結合でない(高スピンの)点だけに CCSD(T) をかける(1 行)。
5. **層の AP.** 低スピン結合の点を層で使う場合(X5 の経路判定、P8 の BS)は、層の LOT で高スピンの SP をとって AP をかける。今の層には AP がないので、これは前提である。
6. **層の汎関数の数値的な健全性**は X7 のベンチマークで選定基準に入れる(M06-2X は TZVP でも h_c2h4 の錯体で未収束)。

**検証(採否の基準を先に宣言する).**
- 点: h_c2h4 3380099b の錯体、S5 の BS 錯体、S6 の TS、CH3O、HONO(閉殻の対照)。
- 基準: 収束する(または上限内に scf_unavailable で閉じる)、⟨S²⟩ のクラスが freq と一致する、時間が上限内。原子推定からの cgmin の成功は 1 例しかないので、梯子の段はこの結果で決める。
- その後、R2 の 41 run を新しい run dir で流す。同じ run dir に追記すると、同じ parent・同じ Level の sp artifact が 2 つ並び、thermo の層の辞書が後勝ちで上書きする。検証は新しい run dir で行うことを規則にする(U8-P2 の代替の「重複は error」もこれを防ぐ)。

### X4 仮説と状態の単位: 状態・事実・問い・鎖

**根本原因.** 同一性と単位の定義が弱く、重なっている。
- 状態はハッシュで、立体がない。
- 比較は帯付きと帯なしが混在。
- 仮説(問い)と、検証済みの素過程(事実)と、結果が 1 つのレコードに同居している。
- 反応の評価に共通のゼロがない。

**設計.**
1. **状態**: RDKit の正準化で状態ラベルを作り(U1-P3)、立体の層を足す(U1-P4)。比較は帯付きの `same_bonding` 1 関数(U1-P2)。入口で元素順に安定ソートする(U3-P5)。
2. **種と事実**:
   - (段階 0、must)Seed が自分の出所のラベル付き結合変化を持つ(U5-P3a)。貸した TS は貸し手の端で測る。等価原子の問題は Hungarian の写像で 1 つの置換を両端に適用する(U6-P2)。
   - (段階 1、should)**状態の対の結論の登録簿**(U5-P3b、U6-P5 段階 1、U9-P9 段階 1、U4-P4)。受理した TS と QRC の両側を、TS の同一性(identity.assign を鞍点にも使う)で重複を除いた無向のエッジとして登録する。BARRIERLESS の経路も同じ型で持つ。
     - same_as と undriven の写しを、エッジの有向の検索に置き換える。向きに依存する判定(窓)は問い合わせ側、向きに依存しない判定(TS・接続)はエッジ側に置く。
     - reassigned はエッジとして登録し、宣言した対の探索は残りの種で続ける。finalize の minima の書き換えを廃止する。
     - Hypothesis(不変)と CaseResult を分ける。
   - (段階 2、could)split、Work.split_ts、ts_calc の貸し出し、`_two_steps`、子の case、waiting、split_depth を、「R→I と I→P の区間をネットワークに問い合わせ、未知の区間だけ種を消費する」に置き換える。U9 の予算と U8 の報告の改修の後に行う。
3. **反応の鎖と共通のゼロ**(U7-P1、U8-P5、U8-P6 を統合した修正形)。
   - `chain_points(rx)` が [R_sep?, R_state, TS…, P_state, P_sep?] を返し、各点が (subject 群, 分子数 n_k) を持つ。
   - **標準状態の補正は点ごとの n_k から各点の G に入れる**(今の shifts は rx の係数から作っていて、鎖の点と対応しない)。
   - 律速の差は δG = max_k (G_k − min_{j≤k, j は井戸} G_j)。min は井戸(分離点、状態)だけでとり、TS を含めない(会合錯体で G_TS < G_R になりうるため)。素反応の単分子では今の effective_barrier と完全に一致する。非周期の直列経路に対する「最低の先行状態から見た最高 TS」であり、Kozuch–Shaik の energetic span は触媒サイクルの定式化なので、引用はその一般化として書く。
   - 反応物の基準は G_ref = min(G_complex, ΣG_frag + shift)。どちらが選ばれたかを行に出す(1 M と 1 atm で約 1.9 kcal/mol 違い、標準状態で切り替わりうる)。S6 は約 10.4 になり、SN2・S10 は錯体基準のまま変わらない。
   - 分離点は宣言組成の (Hill, 電荷) ではなく、端点の状態ラベルの断片から作る。**第 1 段は、端点の断片が宣言単量体と一致する場合に限って適用する。** 断片の DFT 極小を自動で作る規則(U3 の対象への追加)と同時に、R_sep の fail-closed を入れる。単独で入れると、split の子(H2O·CH3)が blocker になって順位から消える。
   - vs_separated は組成の共通のゼロとして残す。dG_assoc は「端点の断片が宣言単量体と一致する場合に限る」にする(split1 の −10.58 が消える)。
   - **障壁のない会合は捕獲律速の区分に移す**: 「ΔG‡ は未定義(捕獲律速)、ΔG_rxn のみ」とし、単分子の段の序数に入れない。層の経路判定(X5)で山が出た場合も、出すのは ΔE‡ の上界(電子エネルギー、節点が離散であることを注記)で、ΔG の序数には入れない。
   - 多段の親の行には鎖の span を付ける。同じ TS は `SaddleClaim.freq_calc` で 1 行にまとめ、逆向きの障壁を列で出す。序数は出発状態ごとにまとめる。
4. **状態の G**: 配座の層が 1 つでも欠ければ None(blocker energy_layer_missing)にする(must)。Boltzmann 和 −RT ln Σ e^{−G_i/RT}(m と σ を各項に含む MS-HO の数え方)は、TS 側の配座集合(U6-P10、登録簿の同チャネル TS)と同時に入れる(should)。

**検証.**
- QM なし: thermo は純関数なので、R2 の manifest で thermo stage だけを再生し、全 ReactionThermo の差分表を作る。単分子の素反応は 1e-9 で不変、S6 は約 10.4、SN2(14.53)と S10(36.64)は不変、split1 の dG_assoc は消える。
- 外部の値とは約 1 kcal/mol の幅で照合する(κ・q_el・層の誤差が同程度ある)。
- 登録簿: R2 の manifest から組み立て、S6 の 1f266f1727 と split1 が 1 本のエッジになること、oxalic と S6 の親の span が子の値から再現されること。fake PES で、最初の種が R→X を結んだ後も探索が続き、P への TS で ELEMENTARY になること。
- 偽合格の兆候: S6 が変わらない(鎖が使われていない)。SN2 まで分離基準に下がる(min の向きの誤り)。断片の極小がないのに黙って錯体基準に戻る。エッジの重複除去が緩く、別の TS をまとめている(ν‡ と E を照合する)。同じ run dir のキャッシュで結論だけを一致させている。

### X5 計算点の選び方: 読まれる点だけを、正しい面で計算する

**根本原因.** 高価な計算の対象を、上流が下流の需要を推測して押し出している(sp._targets、always、mode-follow の freq)。一方で、本当に要る点(経路上の層、TS の DFT//xTB)は計算していない。

**設計.**
1. **需要の 1 関数**(U0-P5、U8-P1、U9-P4 の修正形)。
   - chemistry/thermo の participants の隣に `reaction_points(rx)` を置き、**報告する量ごとに要る点**を返す。
   - 順位の点(G_ref の候補、生成物の状態、TS)は必ず計算し、欠ければ blocker。錯体は、TS がある反応でだけ G_ref の候補になる。障壁のない会合では max(G_P, G_ref) − G_ref に効かないので、順位の点に入れない。
   - 補助の点(前駆錯体の dG_assoc、パネル)は計算するが、失敗はその列の注記にとどめ、順位にも rc にも効かせない。
   - sp stage はこの関数の和集合を計算する stage として残す(thermo を純関数に保つ)。
   - thermo の層の対応付けは (subject, method の full_key) の明示的な辞書にし、重複は error にする。
   - パネル(summary.py:194)と、ranking.csv のパネル幅の列(summary.py:217-225)も同じ関数の基準で出す。
   - 検証: 同じ run dir の再生で新しいジョブ 0、ranking.csv が同一、method_panel.csv の差が会合の行の基準の変化だけで、行が消えていないこと。
   - 偽合格の兆候: ranking が同一なのは `_state_G` が欠けた配座を黙って飛ばしたから(energy_layer_missing の件数と、状態ごとに使った配座の id を比べる)。パネルの会合の行が消えて差がなくなる。
2. **低レベル → DFT の漏斗**(U4-P3)。TS が検証された辺の source・TS・生成物に、DFT//xTB の SP を minima(dft) の rerank の中でかけ、窓・順位・件数の上限を 1 か所で決める。
3. **層を経路に当てる**(U0-P4、U5-P2、U8-P8 の修正形)。
   - 対象は PBE0 で barrierless と判定された case だけ。既存の連続した経路(会合スキャン、SCREEN の NEB と密化点、string)の全節点に層の SP をとる(X3 の射影推定)。低スピン結合の節点では、層で高スピンの SP をとって AP をかける。同じ judge で分類し直す。
   - 山があれば outcome を「順位の LOT で障壁あり」とし、層の経路の最大(推定。節点が離散なので鞍点との大小は決まらず、厳密な上界ではない)を ΔE‡ として出す。ΔG の序数には入れない。熱補正は付けない(非停留点に停留点の熱補正を足すのは不正直)。必要なら U7-P10 の VTST の任意の拡張で扱う。
   - 層の山からの REFINE_SADDLE は成り立たない(PBE0 の面に鞍点がない)。
   - 節点の SCF が 1 本でも失敗したら、その判定は unavailable にする(barrierless としない)。
   - 前提: X3(状態の来歴)と、X7 の層の選定(M06-2X のままでは h_c2h4 の節点が解けない)。走査の範囲の修正(U5-P6)。
   - 検証: h_c2h4(山が resolution を超え、ΔE‡ が NHTBH38 の 1.72 の ±1 kcal/mol に入るか)、bh3_nh3 と S5 の CH3+O2(障壁なしのまま残るか)、S6・HONO(対照)。基準は事前に宣言する。
   - 偽合格の兆候: 1 点だけ別の SCF 解に落ちてできた山(⟨S²⟩ の跳び)。失敗点を落としたプロファイル。錯体基準の山。ΔE と ΔG の混同。

### X7 予算・実行・再現性・検証

**根本原因.** 判定の入力に、記録されない量(壁時計)が混ざっている。rc がジョブの失敗の数で、成果の完全性ではない。再現性をビット単位で定義している。検証がコードの外の運用作業になっている。

**設計.**
1. **予算は件数だけ**(U9-P1 の修正形、must)。
   - 削除するもの: 行 7、Deadline、MIN_ATTEMPT_S、protocols の deadline 引数(5 メソッド)、`_attempt_timeout` の deadline 分岐、actions.py:320 と connection.py:163 の expired、Item の第 3 要素、`deadline or rt.deadline(...)`、walltime_h。
   - 壁時計は run の外側の停止(SIGTERM、バッチの上限)だけに使い、stage を `status: incomplete` で残し、再開ではキャッシュから続ける(`_fresh` は done だけを skip するので、incomplete は自然に再実行される)。
   - 期限継承のバグは構造上消え、hono_walltime は「外側の停止 → incomplete → rc 1」の試験に置き換わる。費用の観測が要るなら Evidence に duration を記録するだけにし、判定には使わない。DRV-01 の止血は不要になる。
   - 検証:
     - fake engine: 子を待ち行列に入れて兄弟が長く走った後でも、子が自分の件数の予算で駆動されること。
     - SIGTERM で paths を途中停止して再起動し、incomplete → done になり、結論が中断なしと一致すること。
   - 偽合格の兆候: incomplete の stage が done として飛ばされる。R2 は予算に当たる case がほぼないので、全件合格でも検証にならない(件数の予算を小さくした系で試す)。
2. **rc は成果の完全性**(U9-P5 の修正形)。
   - rc 0 = 全 stage が完了(化学の UNRESOLVED と、CREST・SCC・補助の点の陰性は coverage に出すだけ)。
   - rc 1 = 運用上の未完(incomplete の stage、error:* の項目)。
   - rc 2 = stage の失敗。
   - 項目の閉じ込めを StageRuntime の 1 か所(thread_map と直列ループで共通)に置き、HFAUTO_STRICT もそこで 1 回だけ見る。drive_case の except は、outcome を UNRESOLVED ではなく failed artifact(error:<型>)にする形でこの写像に吸収する。
   - 期待: S5 と h_c2h4 は 0、hono_walltime は 1。
   - 偽合格の兆候: error を coverage に入れて rc 0 にしてしまう。
3. **環境に起因する失敗は保存しない**(U9-I13)。EXECUTABLE_MISSING と、資源の確保失敗(OOM、GA/MA)に分類した NONZERO_EXIT を volatile にする。化学の失敗(SCF、maxiter、ゲート)とは分ける。
4. **継続**(U9-P3)。結果のない前回の attempt を TIMEOUT として続ける。freq の規模の壁は継続では解けない。根本的な選択肢として「Hessian を変位ごとの勾配ジョブの有限差分として JobStore 上で組み立てる(各ジョブがキャッシュされて再開でき、ノードをまたいで並列化できる。費用は 6N 回の勾配で増えるので、閾値以上の規模に限る)」を、NWChem の数値 Hessian の restart の可否とあわせて実測で判断する(could、要プローブ)。
5. **並列化は段階的に**(U9-P2 の修正形)。
   - (a)(should)Registry への合流がない部分を thread_map に載せる: minima の opt 群と新しい basin の freq(登録は species id 順に直列で行う)、sp の全対象。cancel_futures と scratch_dir の expandvars も直す。
   - (b)(could)case の並列化は、登録簿(X4)の後に世代同期(BSP)で行う。
   - (c)slurm の Executor は実際の HPC の利用者が現れてから作る。
   - (d)ロックは、別ホストの holder を生存として扱う(または lease と heartbeat)ように判定そのものを変える(U9-I14)。
   - 件数の予算(1.)が、並列化を安全に入れる前提になる。core 秒の判定は並列度で変わるためである。
6. **鍵と来歴**(U9-P6 の修正形)。
   - 鍵に、**ExecutionSpec に依らない正準の Setup(scratch なし、memory 固定)で描画した deck の sha** を入れる。置換による正規化は engine ごとの脆い正規表現になり、site の設定が鍵に漏れる。
   - version_pin を {program: version} の辞書にし、preflight で toolchain の指紋を uv.lock と照合する(rdkit のずれは実際に検出されるはず)。
   - manifest に code_version(dirty の印付き)・config_sha・input_sha・toolchain を上書きせずに残す。
   - parser_version による再 parse は could。
   - 鍵の移行は、U9-P8 の engine 名・U9-P10 のハッシュ統一と同じ 1 回にまとめる。
   - 偽合格の兆候: 正規化が強すぎて意味のある変更が消える。移行で全ジョブが miss になるのを「動いた」と見なす(key_document の差分で確かめる)。
7. **検証を repo の中へ**(U9-P7、U0-P2、U8-P9 を統合した修正形、must)。
   - `validation/cases.yaml`: system、pipeline、期待の outcome、状態ラベルの署名、許容幅、参照値と出典。比較は報告(U8-P10)を読む純関数 1 つで行い、concl.py と reach.py を置き換える。
   - 精度の参照: BH76(HTBH38/NHTBH38)の、**既存の検証系と重なる部分集合**(OH+CH4、H+C2H4、HCN↔HNC、Cl⁻+CH3Cl、H+H2 など)を `known_endpoints` の system 群として置く。比べるのは**振動なしの層の ΔE‡**(pipeline の PBE0 構造での値)で、δG_eff とは比べない。参照構造との違いによる誤差も、許容幅の定義に含めて明記する。期待値を変えるときは参照との乖離として記録し、合格にしない。
   - 層の選定: 同じ集合で M06-2X・revM06・ωB97X-D3 の ΔE‡ の MUE と、開殻の弱結合錯体(H···C2H4、CH3···O2、OH···CH4)での SCF の失敗数・反復数を測る。事前の採否基準の例: 類別の MUE が現行以下で、開殻錯体での SCF 失敗 0、費用は 2 倍以内(超えるなら兼ね合いを明記)。ωB97X-D3 は 1 点あたり約 6.6 倍の費用になる。σ_method は design §7.4 の精度の主張にだけ使い、同順位の合成には使わない(U8-P7)。
   - 再現性: 境界の近くで決まる系(S6、h_c2h4、S5 split2)は新規 run を 2 回流し、結論の一致と δG_eff の差を見る。それ以外は strict 再生を回帰に使う。両者の役割を validation.md に明記する。
   - `pytest -m real` に HCN の known_endpoints(約 1 分)の実計算を 1 本入れる。報告のテストは R2 の s6・s5・oxalic の manifest の抜粋を golden にする(出所と sha を SOURCES.json に記録)。テスト本文から repo の外の数値と履歴の ID を消す。
   - 偽合格の兆候: 許容幅を広げて全件合格にする。署名が outcome だけで、生成物の取り違えを見逃す(状態ラベルを必ず含める)。選定用と保留用に同じ反応がある。
